# Ручная проверка Conversion Trace Inspector

Документ проверяет новую вкладку `Конвертации` в Debug Monitor. Трассы содержат
вводимый текст, поэтому тестовые данные не должны включать пароли или другую
чувствительную информацию.

## Подготовка

1. Запустить LSwitch в графической сессии:

   ```bash
   .venv/bin/python -m lswitch --replace --debug
   ```

2. В tray открыть `Debug Monitor`.
3. Убедиться, что по умолчанию выбрана вкладка `Конвертации`, а прежние панели
   `Current State`, `Event Buffer` и `Event Log` находятся только во вкладке
   `Состояние`.
4. Повторить основные сценарии отдельно в доступных X11 и Wayland-сессиях.

## Решения детектора

1. Набрать корректное слово исходной раскладки и завершить его пробелом.
   Ожидается: `KEEP`, решающее совпадение исходного словаря; исполнение не
   запускается.
2. Набрать `ghbdtn` в английской раскладке при активной автоконвертации.
   Ожидается: системный target-prefix конвертирует слово во время набора;
   показаны исходный и преобразованный варианты, языки, достигнутые правила и
   отдельный успешный результат исполнения.
3. Подобрать слово, решение по которому принимает N-граммный анализ.
   Ожидается: видны `source_score`, `target_score`, `delta` и `threshold`, без
   повторного запуска анализа при открытии строки.
4. Проверить положительный и отрицательный вес самообучающегося словаря.
   Ожидается: точные решения и резервирование пользовательского префикса идут
   раньше системных словарей и N-грамм.
5. Включить автоматическую конвертацию и набрать слово постепенно.
   Ожидается: префиксы являются раскрываемыми группами одной строки; строка
   обновляется на месте и до границы слова имеет пометку
   `Набор продолжается`. После Space пометка меняется на `Завершена`.
6. Добиться ранней конвертации префикса, затем дописать остаток слова. Например,
   после `рудд → hell` ввести завершающую `o`.
   Ожидается: после успешной конвертации хвост не анализируется как отдельное
   слово. На `Space` не создаётся повторное решение `SPACE_AUTO`; пробел только
   завершает logical word session и удаляет marker отмены.

## Ручная конвертация и ошибки исполнения

1. Выполнить двойной Shift после набранного слова.
   Ожидается: выбран `buffer retype`, видны delete/layout switch/replay/policy.
2. Выполнить двойной Shift для свежего выделения.
   Ожидается: выбран selection path, а не автоматический детектор.
3. Отменить недавнюю автоконвертацию.
   Ожидается: отдельная запись с trigger `UNDO` и этапом обучения.
4. На тестовом backend-е искусственно вызвать отказ переключения раскладки.
   Ожидается: решение остаётся `CONVERT`, но исполнение имеет `FAILED`, а
   ошибочный этап выделен текстом и значком.

## Управление историей

1. Открыть монитор только после нескольких конвертаций.
   Ожидается: накопленная до открытия история уже видна.
2. Проверить фильтры `Все`, `Конвертированы`, `Оставлены / пропущены`, `Ошибки`
   и поиск по слову, rule ID и локализованной подписи.
3. Выбрать старую строку и создать новую запись.
   Ожидается: выбор сохраняется по `trace_id`.
4. Нажать `Пауза`, создать несколько записей и нажать `Продолжить`.
   Ожидается: во время паузы меняется только счётчик; после продолжения вкладка
   перечитывает актуальный bounded snapshot.
5. Нажать `Копировать трассу`.
   Ожидается: в буфер попадает только выбранная локализованная трасса со
   стабильными rule ID; автоматического копирования нет.
6. Нажать `Очистить`, затем создать ещё одну запись.
   Ожидается: обе панели очищаются, сбор продолжается.
7. Создать более 200 записей.
   Ожидается: самая старая вытесняется, число строк не превышает 200.

## Lifecycle, локализация и внешний вид

1. При открытом мониторе выключить `debug` в настройках.
   Ожидается: история немедленно удаляется, вкладка сообщает, что трассировка
   выключена; окно принудительно не закрывается.
2. Запустить процесс с `--trace` и выключить config `debug`.
   Ожидается: effective debug и recorder остаются активными до завершения
   процесса.
3. Несколько раз закрыть и открыть Debug Monitor.
   Ожидается: события не дублируются, backlog сохраняется в recorder-е.
4. Проверить RU и EN locale, светлую и тёмную тему, управление клавиатурой и
   длинный selection более 256 символов.
   Ожидается: строки локализованы, статусы различимы не только цветом, текст в
   detail переносится, длинное значение имеет явную отметку обрезки.
