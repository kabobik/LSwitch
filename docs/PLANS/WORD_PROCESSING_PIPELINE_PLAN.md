# Pipeline обработки слова

Дата: 2026-07-13

Статус: архитектура и реализация завершены 2026-07-13. Автоматические тесты
пройдены; ручная проверка X11/Wayland выполняется по отдельным сценариям.

## 1. Цель

Сформировать единый и явно заданный порядок принятия решения об автоматической
конвертации раскладки. Убрать захардкоженные мини-словари из приложения и
использовать три источника решений:

1. пользовательскую историю решений `user_dict`;
2. системные Hunspell/MySpell-словари;
3. n-gram-анализ как последний источник вероятностного сигнала.

Основное решение принимается во время набора. На границе слова остаётся только
разрешение неоднозначного результата через строгий n-gram fallback. Короткий
префикс не обладает той же достоверностью, что и завершённое слово, поэтому
n-gram не запускается до Space.

## 2. Термины

- **Исходное слово** — текст, набранный в текущей раскладке.
- **Преобразованное слово** — тот же набор физических клавиш, отображённый в
  противоположной раскладке.
- **Source language** — язык текущей раскладки.
- **Target language** — язык противоположной раскладки.
- **KEEP** — оставить введённый текст без изменения.
- **CONVERT** — заменить его преобразованным вариантом и переключить раскладку
  согласно текущей политике исполнения.
- **SKIP** — не запускать детекторы из-за входного ограничения.
- **WAIT** — не принимать решение для недописанного слова и дождаться
  следующего символа либо границы слова.
- **Доступен словарь** — словарь включён и успешно загружен.
- **Промах словаря** — доступный словарь проверен, но слово в нём не найдено.
  Промах нельзя смешивать с недоступностью словаря.

`user_dict` является не лингвистическим словарём, а накопленной
пользовательской политикой. Для пары «набранное слово + текущая раскладка» он
хранит уверенность в действиях `convert` и `keep`.

## 3. Исходное состояние до реализации

### 3.1 Завершённое слово

Сейчас `AutoDetector` выполняет проверки в таком порядке:

```text
candidate guards
  -> user_dict
  -> встроенные en_words.py / ru_words.py
  -> n-gram delta
  -> n-gram zero-source heuristic
  -> KEEP
```

Системные словари в этом пути не используются. `DictionaryService` загружает
захардкоженные наборы из `lswitch/intelligence/en_words.py` и
`lswitch/intelligence/ru_words.py`. На момент подготовки документа это 574
английских и 347 русских слов.

### 3.2 Недописанное слово

Текущий mid-word путь выглядит так:

```text
prefix guards
  -> source prefix lookup
  -> target prefix lookup
  -> user_dict protection
  -> CONVERT
```

Префиксный индекс объединяет встроенные слова с системными словарями.
Системные Hunspell/MySpell-словари загружаются только при одновременно
включённых `auto_switch_mid_word` и `system_dict_enabled`.

### 3.3 Ограничение текущего системного загрузчика

`SystemDictionaryLoader` читает словоформы непосредственно из `.dic` и удаляет
Hunspell-флаги после `/`. Правила образования словоформ из `.aff` пока не
разворачиваются. Поэтому загруженный набор полезен для membership/prefix
проверок, но не эквивалентен полноценной проверке Hunspell.

## 4. Общие принципы нового pipeline

1. Явное решение пользователя имеет приоритет над общими моделями.
2. Детерминированное словарное доказательство имеет приоритет над
   вероятностным n-gram-анализом.
3. При равной или недостаточной уверенности выбирается `KEEP`.
4. Отсутствие загруженного словаря не считается словарным промахом.
5. GUI и Conversion Trace Inspector отображают уже принятое решение и не
   запускают обработчики повторно.
6. Каждый следующий слой запускается только тогда, когда предыдущий не принял
   окончательного решения.
7. Ручная конвертация не проходит через автоматический pipeline. Она остаётся
   явным действием пользователя и может обучать `user_dict`.
8. Автоматического обучения нет. `user_dict` изменяется только явным действием
   Shift+Shift: ручной конвертацией либо отменой автоматической конвертации.
9. `auto_switch` является единым master-переключателем pipeline.
   `auto_switch_mid_word` и `user_dict_auto_confirm` удаляются.

## 5. Pipeline на границе слова

Space больше не запускает повторную target-проверку системного словаря. Он
разрешает только те сессии, в которых mid-word pipeline не выполнил
конвертацию:

```text
word boundary
  -> mid-word conversion already succeeded? finalize only
  -> exact user decision not resolved earlier?
  -> exact source-system veto
  -> strict n-gram fallback
  -> KEEP by default
```

### 5.1 Уже конвертированная сессия

После успешной mid-word конвертации typed buffer сбрасывается, а последующие
символы образуют только хвост видимого слова. Поэтому Space не должен подавать
этот хвост в `AutoDetector`.

На границе выполняются только:

- финализация logical word session и активных trace-сегментов;
- истечение marker, доступного до границы для ручной отмены;
- обычная доставка Space приложению.

Обучения при этом не происходит.

### 5.2 Пользовательское решение на границе

Обычно точный пользовательский `CONVERT` уже исполняется во время набора, а
точный `KEEP` блокирует нижележащие обработчики. Повторная точная проверка на
границе нужна только для разрешения пользовательской коллизии, когда короткая
запись имеет более длинного descendant с противоположным действием.

Правильный результат на Space однозначен, потому что слово завершено:

- точный `CONVERT` — конвертировать;
- точный `KEEP` — оставить;
- только proper-prefix совпадение — считать его завершившимся без точного
  пользовательского решения и перейти к source veto.

### 5.3 Системный source veto

Системный словарь на Space ничего не конвертирует. Проверяется только точное
наличие исходного слова:

```text
source_dictionary.contains(source_word) -> KEEP
```

Это запрещает n-gram менять известное корректное слово. Target dictionary на
границе повторно не проверяется: его evidence уже использовался prefix
pipeline во время набора.

### 5.4 N-gram как последний шанс

N-gram запускается только для целого неконвертированного слова, которое не
защищено точным `user_dict` и не найдено как точное source-слово.

Для сохранения текущей чувствительности без небезопасного special case
фиксируется правило:

```text
target_score > 0
target_score - source_score > 0.05
```

Если условие не выполнено, результат — `KEEP`. Текущее правило
`source_score == 0 and len(word) >= 4` удаляется: оно допускает конвертацию при
нулевых score обоих вариантов.

`auto_switch_threshold` продолжает задавать минимальную длину boundary
кандидата для n-gram fallback. Пользовательские точные решения и системный
mid-word detector от этого порога не зависят.

### 5.5 Результат по умолчанию

Если ни один слой не доказал необходимость конвертации, возвращается `KEEP` с
причиной `no_evidence`. Неизвестное слово само по себе не является
доказательством неправильной раскладки.

## 6. Pipeline недописанного слова

Согласованный порядок:

```text
basic prefix gates
  -> exact user decision
  -> user prefix reservation
  -> system minimum length gate
  -> system source prefix
  -> system target prefix
  -> WAIT
```

N-gram по умолчанию не используется до границы слова. На коротких и постоянно
изменяющихся префиксах его оценки нестабильны и могут приводить к ранним ложным
переключениям.

### 6.1 Базовые ограничения префикса

- префикс непустой;
- раскладка поддерживается;
- символы принадлежат ожидаемому алфавиту;
- регистр соответствует принятой mid-word политике.

`mid_word_min_prefix_len` не входит в базовые ограничения: вручную выученному
короткому слову нужно доверять. Порог применяется позднее только к системному
prefix lookup.

### 6.2 Пользовательский policy lookup

Для нормализованной пары `(typed_prefix, source_language)` lookup возвращает:

- точное активное действие `CONVERT` или `KEEP`;
- наличие более длинных пользовательских записей с этим префиксом;
- наличие более длинного descendant с противоположным действием.

Таблица решений:

| User state | Решение |
|---|---|
| точный `CONVERT`, нет противоположного descendant | `CONVERT` немедленно |
| точный `CONVERT`, есть более длинный `KEEP` | `WAIT` до продолжения или Space |
| точный `KEEP` | не конвертировать на текущем префиксе |
| только proper-prefix пользовательской записи | `WAIT`, system lookup запрещён |
| пользовательское совпадение отпало | перейти к system lookup |

Так пользовательский словарь резервирует свой префикс и не позволяет
системному target prefix преждевременно перехватить слово. Точное действие не
распространяется автоматически на произвольную часть слова.

Пример внутренней коллизии:

```text
foo    -> CONVERT
foobar -> KEEP
```

На `foo` выполняется `WAIT`, потому что немедленная конвертация сделала бы
`foobar` недостижимым в исходной раскладке. На Space точный `foo` однозначно
конвертируется; при продолжении до `foobar` применяется точный `KEEP`.

Для lookup создаётся отдельный prefix index `user_dict`, обновляемый сразу
после ручного обучения и при внешней перезагрузке файла.

### 6.3 Системные префиксы

Если пользовательский lookup не удерживает префикс, сначала проверяется
`mid_word_min_prefix_len`. Более короткий неизвестный префикс получает `WAIT`.

При доступности обоих индексов:

| Source prefixes | Target prefixes | Решение |
|---:|---:|---|
| больше 0 | любое значение | `WAIT/KEEP` |
| 0 | больше 0 | `CONVERT` |
| 0 | 0 | `WAIT` до следующего символа или границы |

Если оба языка имеют такой префикс, продолжается набор в текущей раскладке.
Раннее переключение допускается только при отсутствии source prefix и наличии
target prefix.

### 6.4 Поведение на границе

Успешная user/system mid-word конвертация помечает logical word session как
уже обработанную. На Space detector для хвоста не запускается.

Если mid-word не выполнил конвертацию, после Space запускается только fallback
из раздела 5: точное пользовательское разрешение коллизии, source-system veto
и строгий n-gram.

## 7. Недоступные или частично доступные словари

Согласована следующая безопасная деградация:

- `user_dict` exact/prefix policy работает независимо от системных словарей;
- оба системных словаря доступны — полный system prefix pipeline;
- хотя бы один системный словарь недоступен — system prefix conversion
  отключается целиком, потому что невозможно безопасно доказать отсутствие
  source prefix одновременно с наличием target prefix;
- доступный source dictionary всё ещё может поставить exact veto на Space;
- если source dictionary недоступен, boundary переходит от нейтрального
  `user_dict` сразу к строгому n-gram;
- оба словаря недоступны — остаются ручное обучение, точные пользовательские
  решения и n-gram fallback.

GUI должен явно сообщать о деградированном режиме. В трассе состояния
`UNAVAILABLE` и `NOT_MATCHED` должны отображаться раздельно.

## 9. Предлагаемая архитектура источников

Один загрузочный компонент формирует immutable snapshot:

```text
SystemDictionaryLoader
  -> SystemLexiconSnapshot
       en_words
       ru_words
       source statuses
       paths
       availability
  -> FullWordDictionary
  -> PrefixDictionary
```

`MidWordDetector` получает prefix lookup, а boundary fallback — exact source
lookup, построенные из одного snapshot. Компоненты не должны сами знать пути,
читать файлы или обращаться к GUI-конфигурации.

Отдельное представление пользовательской политики:

```text
UserDictionary
  -> UserPolicyIndex
       exact action + weight
       has descendants
       has opposite-action descendants
```

Индекс обновляется в памяти после каждого ручного изменения. Внешняя
перезагрузка `user_dict.toml` также инвалидирует индекс.

## 10. Трассировка решения

Conversion Trace Inspector должен показывать последовательность реально
достигнутых правил:

```text
candidate.valid
midword.user_dictionary.exact_convert
midword.user_dictionary.exact_keep
midword.user_dictionary.prefix_reserved
midword.source_prefix
midword.target_prefix
auto.source_dictionary.match
auto.ngram.min_length
auto.ngram.delta
auto.no_evidence
```

Для каждого словарного шага нужны как минимум:

- язык;
- проверенное слово или префикс;
- `MATCHED`, `NOT_MATCHED` либо `UNAVAILABLE`;
- путь к активному `.dic`;
- число загруженных слов.

Для n-gram шага:

- `source_score`;
- `target_score`;
- `delta`;
- `minimum_target_confidence`;
- `delta_threshold`.

После решающего шага нижележащие обработчики не запускаются и не должны
изображаться как выполненные.

## 11. Выполненные этапы реализации

### Этап 0. Characterization — выполнен

- зафиксировать текущий порядок и результаты на репрезентативном наборе слов;
- отдельно собрать примеры ложных срабатываний `zero_source`;
- определить ожидаемые решения при совпадении слова в обоих языках;
- зафиксировать поведение при отсутствии одного или обоих `.dic`.

### Этап 1. Единый системный snapshot — выполнен

- отделить загрузку слов от `PrefixDictionary`;
- создать единое состояние доступности и metadata;
- передавать snapshot в exact source и prefix lookup;
- сохранить атомарное live-применение настроек.

### Этап 2. User policy index и явное обучение — выполнен

- добавить exact/prefix/opposite-descendant lookup;
- обновлять индекс после ручного Shift+Shift обучения;
- удалить `user_dict_auto_confirm` и автоматическую запись на Space;
- покрыть точные решения и коллизии prefix reservation тестами.

### Этап 3. Новый mid-word pipeline — выполнен

- выполнять user exact/prefix policy перед минимальной длиной и system lookup;
- использовать только системный prefix index;
- реализовать безопасную деградацию при недоступных индексах;
- покрыть lifecycle и раннюю конвертацию тестами.

### Этап 4. Облегчённый boundary fallback — выполнен

- не запускать detector после успешной mid-word конвертации;
- сохранить boundary lifecycle и marker expiration без обучения;
- добавить exact source-system veto;
- оставить только строгий n-gram fallback и удалить `zero_source`;
- покрыть хвост после ранней конвертации и неразрешённые слова тестами.

### Этап 5. Удаление встроенных слов и старых настроек — выполнен

- удалить модули мини-словарей и все ссылки на `builtin`;
- удалить `auto_switch_mid_word` и сделать `auto_switch` master toggle;
- обновить тестовые fixtures, GUI, README и installer messaging;
- выполнить полный regression и ручную проверку X11/Wayland.

## 12. Зафиксированные дополнительные решения

1. `system_dict_enabled` остаётся пользовательским переключателем. При его
   выключении продолжают работать user policy и boundary n-gram.
2. `auto_switch` становится единым master toggle;
   `auto_switch_mid_word` удаляется.
3. `auto_switch_threshold` применяется только к boundary n-gram fallback.
4. `user_dict_auto_confirm` удаляется; обучение происходит только через
   Shift+Shift.
5. Положительный точный `user_dict` конвертирует во время набора, кроме
   коллизии с более длинным пользовательским `KEEP`.
6. N-gram сохраняет delta `> 0.05`, требует положительный target score и не
   имеет `zero_source` special case. Новый GUI-порог в этой задаче не вводится.
7. Поддержка Hunspell `.aff` не входит в эту реализацию.
8. Имя `user_dict` сохраняется для совместимости; переименование может быть
   отдельным последующим изменением.

## 13. Критерии готовности

- в runtime отсутствуют встроенные наборы слов;
- mid-word использует `user exact -> user reservation -> system prefixes`;
- точный пользовательский `CONVERT` исполняется без ожидания Space;
- пользовательский proper prefix блокирует system lookup до exact match или
  расхождения;
- boundary не повторяет target dictionary conversion;
- после успешной mid-word конвертации boundary не анализирует хвост слова;
- неразрешённый boundary использует `user exact -> source veto -> n-gram`;
- n-gram не конвертирует слово без положительного target evidence;
- автоматического обучения `user_dict` нет;
- отсутствие словаря отличается от отсутствия слова;
- exact source и prefix lookup используют один системный snapshot;
- live-настройки атомарно обновляют оба пути;
- trace показывает точный short-circuit порядок;
- тесты не зависят от содержимого `/usr/share/hunspell`;
- отсутствие системных словарей заметно пользователю, отключает system
  mid-word stage, но сохраняет user policy и boundary n-gram fallback.

## 14. Результат реализации

- `SystemLexiconSnapshot` загружает EN/RU один раз и питает exact/prefix
  представления;
- live-reload публикует новый snapshot одновременно всем потребителям;
- `user_dict` принимает точные решения и резервирует пользовательские
  префиксы до системного этапа;
- обработанное mid-word слово не проверяется повторно по хвосту на `Space`;
- boundary использует source-only lookup и строгий n-gram fallback;
- встроенные мини-словари и оба устаревших config-параметра удалены;
- автоматический regression: `1052 passed` (2026-07-13).
