# Pipeline обработки слова

Дата: 2026-07-13

Статус: черновик для обсуждения. Реализация не начата.

## 1. Цель

Сформировать единый и явно заданный порядок принятия решения об автоматической
конвертации раскладки. Убрать захардкоженные мини-словари из приложения и
использовать три источника решений:

1. пользовательскую историю решений `user_dict`;
2. системные Hunspell/MySpell-словари;
3. n-gram-анализ как последний источник вероятностного сигнала.

Для завершённого слова и недописанного слова нужны разные pipeline. Короткий
префикс не обладает той же достоверностью, что и слово на границе, поэтому
n-gram не должен автоматически применяться к обоим режимам одинаково.

## 2. Термины

- **Исходное слово** — текст, набранный в текущей раскладке.
- **Преобразованное слово** — тот же набор физических клавиш, отображённый в
  противоположной раскладке.
- **Source language** — язык текущей раскладки.
- **Target language** — язык противоположной раскладки.
- **KEEP** — оставить введённый текст без изменения.
- **CONVERT** — заменить его преобразованным вариантом и переключить раскладку
  согласно текущей политике исполнения.
- **SKIP** — не запускать детекторы из-за входного ограничения.
- **WAIT** — не принимать решение для недописанного слова и дождаться
  следующего символа либо границы слова.
- **Доступен словарь** — словарь включён и успешно загружен.
- **Промах словаря** — доступный словарь проверен, но слово в нём не найдено.
  Промах нельзя смешивать с недоступностью словаря.

`user_dict` является не лингвистическим словарём, а накопленной
пользовательской политикой. Для пары «набранное слово + текущая раскладка» он
хранит уверенность в действиях `convert` и `keep`.

## 3. Текущее состояние

### 3.1 Завершённое слово

Сейчас `AutoDetector` выполняет проверки в таком порядке:

```text
candidate guards
  -> user_dict
  -> встроенные en_words.py / ru_words.py
  -> n-gram delta
  -> n-gram zero-source heuristic
  -> KEEP
```

Системные словари в этом пути не используются. `DictionaryService` загружает
захардкоженные наборы из `lswitch/intelligence/en_words.py` и
`lswitch/intelligence/ru_words.py`. На момент подготовки документа это 574
английских и 347 русских слов.

### 3.2 Недописанное слово

Текущий mid-word путь выглядит так:

```text
prefix guards
  -> source prefix lookup
  -> target prefix lookup
  -> user_dict protection
  -> CONVERT
```

Префиксный индекс объединяет встроенные слова с системными словарями.
Системные Hunspell/MySpell-словари загружаются только при одновременно
включённых `auto_switch_mid_word` и `system_dict_enabled`.

### 3.3 Ограничение текущего системного загрузчика

`SystemDictionaryLoader` читает словоформы непосредственно из `.dic` и удаляет
Hunspell-флаги после `/`. Правила образования словоформ из `.aff` пока не
разворачиваются. Поэтому загруженный набор полезен для membership/prefix
проверок, но не эквивалентен полноценной проверке Hunspell.

## 4. Общие принципы нового pipeline

1. Явное решение пользователя имеет приоритет над общими моделями.
2. Детерминированное словарное доказательство имеет приоритет над
   вероятностным n-gram-анализом.
3. При равной или недостаточной уверенности выбирается `KEEP`.
4. Отсутствие загруженного словаря не считается словарным промахом.
5. GUI и Conversion Trace Inspector отображают уже принятое решение и не
   запускают обработчики повторно.
6. Каждый следующий слой запускается только тогда, когда предыдущий не принял
   окончательного решения.
7. Ручная конвертация не проходит через автоматический pipeline. Она остаётся
   явным действием пользователя и может обучать `user_dict`.

## 5. Pipeline завершённого слова

Предлагаемый порядок:

```text
input gates
  -> build source/target candidates
  -> user decision policy
  -> system dictionary evidence
  -> strict n-gram evidence
  -> KEEP by default
```

### 5.1 Входные ограничения

До обращения к источникам решения проверяются:

- наличие непустого слова;
- поддерживаемая текущая раскладка;
- допустимый алфавитный состав;
- минимальная настроенная длина буфера;
- возможность построить преобразованный вариант и определить target language.

Нарушение ограничения даёт `SKIP`, а не `KEEP`: обработка не состоялась.

### 5.2 Пользовательская политика

Проверяется точная нормализованная пара:

```text
(typed_word, source_language)
```

Результат:

- вес `>= user_dict_min_weight` — немедленный `CONVERT`;
- вес `<= -user_dict_min_weight` — немедленный `KEEP`;
- вес между порогами или отсутствие записи — переход к системным словарям.

И положительное, и отрицательное решение пользователя перекрывает системный
словарь и n-gram.

### 5.3 Системные словари

Проверяются два независимых факта:

```text
source_match = source_dictionary.contains(source_word)
target_match = target_dictionary.contains(target_word)
```

При доступности обоих словарей применяется безопасная таблица решений:

| Source match | Target match | Решение |
|---|---|---|
| да | нет | `KEEP` |
| нет | да | `CONVERT` |
| да | да | `KEEP` |
| нет | нет | перейти к n-gram |

Если оба варианта являются словами, приоритет получает исходный вариант. Такое
поведение минимизирует ложные автоматические исправления. Явный `user_dict`
может переопределить этот результат.

### 5.4 N-gram как последний шанс

N-gram запускается только когда пользовательская политика нейтральна, а
системные словари не дали окончательного ответа.

Для `CONVERT` должны одновременно выполняться два условия:

```text
target_score >= minimum_target_confidence
target_score - source_score >= delta_threshold
```

Если хотя бы одно условие не выполнено, результат — `KEEP`.

Текущее правило `source_score == 0 and len(word) >= 4` предлагается удалить.
Оно может конвертировать слово даже тогда, когда `target_score` также равен
нулю, то есть положительного сигнала в пользу target language нет.

Значения `minimum_target_confidence`, `delta_threshold` и минимальная длина для
n-gram должны быть зафиксированы отдельным решением после проверки текущих
моделей и набора примеров.

### 5.5 Результат по умолчанию

Если ни один слой не доказал необходимость конвертации, возвращается `KEEP` с
причиной `no_evidence`. Автоматический pipeline не должен конвертировать слово
только потому, что оно неизвестно.

## 6. Pipeline недописанного слова

Предлагаемый безопасный порядок:

```text
prefix gates
  -> user protection / exact learned decision
  -> system source prefix
  -> system target prefix
  -> WAIT
```

N-gram по умолчанию не используется до границы слова. На коротких и постоянно
изменяющихся префиксах его оценки нестабильны и могут приводить к ранним ложным
переключениям.

### 6.1 Ограничения префикса

- префикс непустой;
- длина не меньше `mid_word_min_prefix_len`;
- раскладка поддерживается;
- символы принадлежат ожидаемому алфавиту;
- регистр соответствует принятой mid-word политике.

До достижения минимальной длины возвращается `WAIT/SKIP`, но логическая сессия
слова сохраняется.

### 6.2 Пользовательская политика для префикса

Отрицательная запись `user_dict` защищает соответствующий префикс и его
продолжение от ранней конвертации. Такая защита должна проверяться до
системного prefix lookup.

Положительную запись нельзя автоматически распространять на всё поддерево
префиксов. Возможный безопасный вариант — применять её только при точном
совпадении текущего префикса с ранее выученным полным словом. Это остаётся
открытым продуктовым решением.

### 6.3 Системные префиксы

При доступности обоих индексов:

| Source prefixes | Target prefixes | Решение |
|---:|---:|---|
| больше 0 | любое значение | `WAIT/KEEP` |
| 0 | больше 0 | `CONVERT` |
| 0 | 0 | `WAIT` до следующего символа или границы |

Если оба языка имеют такой префикс, продолжается набор в текущей раскладке.
Раннее переключение допускается только при отсутствии source prefix и наличии
target prefix.

### 6.4 Поведение на границе

Если mid-word не принял решение, после Space слово проходит полный pipeline из
раздела 5. Если ранняя конвертация уже произошла, дописанный хвост и проверка на
границе остаются связанными одним correlation ID в Conversion Trace Inspector.

## 7. Недоступные или частично доступные словари

Предварительно предлагается следующая безопасная деградация:

- оба словаря доступны — полный pipeline;
- source dictionary доступен и содержит исходное слово — `KEEP` допустим даже
  при недоступном target dictionary;
- source dictionary недоступен — одно target-совпадение не должно само по себе
  вызывать конвертацию, потому что корректность исходного слова неизвестна;
- неполное словарное доказательство передаётся в строгий n-gram слой;
- оба словаря недоступны — завершённые слова обрабатываются только `user_dict`
  и строгим n-gram;
- mid-word отключается, если нет обоих необходимых prefix indexes.

GUI должен явно сообщать о деградированном режиме. В трассе состояния
`UNAVAILABLE` и `NOT_MATCHED` должны отображаться раздельно.

## 8. Удаление встроенного мини-словаря

В рамках реализации потребуется:

1. Удалить `lswitch/intelligence/en_words.py` и
   `lswitch/intelligence/ru_words.py`.
2. Удалить ленивые импорты этих модулей из `DictionaryService`.
3. Сделать системные словари единственным лингвистическим источником полного
   слова и префиксов.
4. Перестать добавлять источник `kind="builtin"` в `PrefixDictionary` и trace
   metadata.
5. Загружать системные словари для boundary auto-conversion, а не только для
   mid-word.
6. Переиспользовать один immutable snapshot словарей в full-word и prefix
   индексах, не читая `.dic` дважды.
7. Перестраивать оба представления атомарно при live-изменении путей или
   `system_dict_enabled`.
8. Пересмотреть GUI-зависимости: пути системных словарей больше не являются
   исключительно дочерними настройками `auto_switch_mid_word`.
9. Обновить README, пример `config.toml`, installer diagnostics и Conversion
   Trace Inspector.
10. Перевести unit-тесты на явно переданные маленькие наборы слов. Тесты не
    должны зависеть от словарей, установленных на машине разработчика или CI.

## 9. Предлагаемая архитектура источников

Один загрузочный компонент формирует immutable snapshot:

```text
SystemDictionaryLoader
  -> SystemLexiconSnapshot
       en_words
       ru_words
       source statuses
       paths
       availability
  -> FullWordDictionary
  -> PrefixDictionary
```

`AutoDetector` получает интерфейс full-word lookup, а `MidWordDetector` —
prefix lookup, построенный из того же snapshot. Детекторы не должны сами знать
пути, читать файлы или обращаться к GUI-конфигурации.

## 10. Трассировка решения

Conversion Trace Inspector должен показывать последовательность реально
достигнутых правил:

```text
candidate.valid
auto.user_dictionary.*
auto.system_dictionary.source
auto.system_dictionary.target
auto.ngram.delta
auto.no_evidence
```

Для каждого словарного шага нужны как минимум:

- язык;
- проверенное слово или префикс;
- `MATCHED`, `NOT_MATCHED` либо `UNAVAILABLE`;
- путь к активному `.dic`;
- число загруженных слов.

Для n-gram шага:

- `source_score`;
- `target_score`;
- `delta`;
- `minimum_target_confidence`;
- `delta_threshold`.

После решающего шага нижележащие обработчики не запускаются и не должны
изображаться как выполненные.

## 11. Предварительные этапы реализации

### Этап 0. Characterization

- зафиксировать текущий порядок и результаты на репрезентативном наборе слов;
- отдельно собрать примеры ложных срабатываний `zero_source`;
- определить ожидаемые решения при совпадении слова в обоих языках;
- зафиксировать поведение при отсутствии одного или обоих `.dic`.

### Этап 1. Единый системный snapshot

- отделить загрузку слов от `PrefixDictionary`;
- создать единое состояние доступности и metadata;
- передавать snapshot в full-word и prefix lookup;
- сохранить атомарное live-применение настроек.

### Этап 2. Новый boundary pipeline

- подключить `user_dict -> system dictionary -> strict n-gram`;
- удалить `zero_source` либо заменить согласованным строгим правилом;
- обновить structured decisions и trace rule IDs;
- покрыть таблицу решений тестами.

### Этап 3. Новый mid-word pipeline

- перенести user protection перед prefix lookup;
- использовать только системный prefix index;
- реализовать безопасную деградацию при недоступных индексах;
- покрыть lifecycle и раннюю конвертацию тестами.

### Этап 4. Удаление встроенных слов

- удалить модули мини-словарей и все ссылки на `builtin`;
- обновить тестовые fixtures, GUI, README и installer messaging;
- выполнить полный regression и ручную проверку X11/Wayland.

## 12. Открытые решения

Перед реализацией нужно согласовать:

1. Оставлять ли `system_dict_enabled` пользовательским переключателем или
   считать системный словарь обязательной частью включённой автоконвертации.
2. Разрешать ли n-gram-only режим при отсутствии системных словарей либо
   полностью отключать boundary auto-conversion.
3. Какое минимальное абсолютное значение `target_score` считать достаточным.
4. Какой `delta_threshold` использовать и должен ли он настраиваться в GUI.
5. Применять ли положительный `user_dict` к точному совпадению незавершённого
   префикса или использовать его только после границы слова.
6. Входит ли поддержка Hunspell `.aff` в эту задачу или остаётся отдельным
   последующим улучшением.
7. Следует ли переименовать `user_dict` в коде и GUI, чтобы подчеркнуть, что это
   история пользовательских решений, а не обычный словарь слов.

## 13. Предварительные критерии готовности

- в runtime отсутствуют встроенные наборы слов;
- boundary pipeline имеет порядок `user -> system -> n-gram -> KEEP`;
- mid-word использует `user protection -> system prefixes -> WAIT`;
- n-gram не конвертирует слово без положительного target evidence;
- совпадение source и target по умолчанию даёт `KEEP`;
- отсутствие словаря отличается от отсутствия слова;
- full-word и prefix lookup используют один системный snapshot;
- live-настройки атомарно обновляют оба пути;
- trace показывает точный short-circuit порядок;
- тесты не зависят от содержимого `/usr/share/hunspell`;
- отсутствие системных словарей заметно пользователю и не приводит к
  агрессивной mid-word конвертации.
